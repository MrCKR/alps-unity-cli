# 已运行 Editor Play 模式的私有字段监听：Unity 官方文档边界

**结论：Unity Editor 自带的启动命令行不支持向已运行的 Play 模式 Editor 零预装地注入任意私有字段写入监听器。** `-executeMethod` 是**打开项目时**执行项目中已有的静态方法，不是向现有 Editor 注入调用；`-batchmode` 启动独立的非交互 Editor，且同一项目已打开时不能再以 batchmode 打开。参见 [Editor 命令行参数](https://docs.unity3d.com/Manual/EditorCommandLineArguments.html)。另有实验性 `com.unity.pipeline` 包提供独立的 `unity command` 热重载能力，但需要提前安装并为目标方法插入分派入口，不能直接拦截未标记的任意字段赋值。[Unity Pipeline 热重载](https://docs.unity3d.com/Packages/com.unity.pipeline@0.6/manual/hot-reload.html)。

| 路径 | 初次项目编译/导入 | 跨重载 | 时效与前提 |
| --- | --- | --- | --- |
| 已有 `Editor.log`、Profiler 数据 | 无 | 仅现有日志/采样产物可继续观察，不构成私有字段回调 | 可读已经输出的日志和已埋点的性能数据；Profiler 的普通采样针对标记，Deep Profile 记录方法调用而非任意字段写入。无法从未记录的字段推断每次跃迁。[日志文件](https://docs.unity3d.com/Manual/log-files.html) · [Profiler 深度分析](https://docs.unity3d.com/Manual/profiler-deep-profiling.html) · [自定义 Profiler 数据](https://docs.unity3d.com/Manual/profiler-customizing.html) |
| Unity Pipeline 0.6.0-exp.1 热重载 | 安装包并对目标方法加 `[HotReload]` 或分派入口时需首次导入/编译；后续 `unity command reload_file` 只在内存中编译新方法体 | 包内 watcher 文档声明可跨域重载恢复覆盖方法；未标记方法不会自动受控 | 适合预先选定的方法，不是任意字段写入钩子；直接 CLI 需要 Pipeline 自身 server，可用性取决于目标项目安装与配置。[热重载机制](https://docs.unity3d.com/Packages/com.unity.pipeline@0.6/manual/hot-reload.html) |
| 已在运行 Editor 内的 Editor 监视器（事先编译、已注册接收命令的入口） | 本次无；前提是**事先**部署并编译 | 可在每次重载后重新初始化、恢复基线并重新定位对象；重载期间不能无间断监听 | 可按 Editor tick 反射读取目标对象的私有字段，比较前后值并在监视器里记日志；对象定位、字段名及权限须准确。`EditorApplication.update` 与 Play 模式更新不同步、频率可变，短暂中间值可能漏掉；这是**检测到变化**的回调，不是赋值瞬间的写屏障。Unity Editor 自带启动命令行没有该监视器的通用远程命令通道；可选 Pipeline 包或本仓库 `code.execute` 属于独立运行时入口。[Editor 更新回调](https://docs.unity3d.com/ScriptReference/EditorApplication-update.html) · [命令行边界](https://docs.unity3d.com/Manual/EditorCommandLineArguments.html) |
| 新增独立 Editor C# 监视脚本（不修改游戏 C# 源码） | **需要**在项目内初次编译并导入/重载；不保证原游戏程序集完全不受刷新影响 | 可在重载后重建监视器，不能保证窗口内的跃迁无损 | Play 中脚本变化的偏好设置可选择继续运行（非序列化状态有风险）、停止 Play 或延迟到 Play 结束；不能同时要求立刻生效且完全无扰动。[Asset Database 刷新](https://docs.unity3d.com/Manual/AssetDatabaseRefreshing.html) · [Play 中脚本变更设置](https://docs.unity3d.com/Manual/preferences-general.html) |
| 导入外部预编译 Editor DLL 到项目 | **可免项目内编译该 DLL 源码**，但仍需导入代码资产并触发刷新/重载；不保证项目其他程序集不被重新编译 | 同上，需要重新绑定 | 监视精度仍受 Editor tick 限制；既有 Play 运行状态也会受到重载影响，不能视为无扰动热注入。[Asset Database 刷新](https://docs.unity3d.com/Manual/AssetDatabaseRefreshing.html) · [Editor 更新回调](https://docs.unity3d.com/ScriptReference/EditorApplication-update.html) |
| 已有 CLI 在当前域中动态加载预编译程序集 | 不改 Assets 不触发项目脚本编译；本仓库 `code.execute` 的装载代码本身会经 Unity 自带 csc 编译 | 手动装载的程序集随域卸载；需要预装引导器或外部进程重挂 | 可把 hook 逻辑预编译并在当前 Editor 执行；无法凭动态加载本身获得跨域重载自动恢复。[本仓库装载实现](../unitypkg/Editor/Infrastructure/CodeExecSupport.cs) · [代码生命周期](https://docs.unity3d.com/Manual/programming-code-lifecycle.html) |
| 附加受支持的托管调试器 | 无项目编译（需 Editor 的 Debug 代码优化模式及可用符号/调试器） | 官方文档未保证断线/重载自动恢复断点 | 官方明确支持断点、单步、暂停时检查变量；断点会令 Editor 停住，故不是无暂停的日志回调。[Unity 托管代码调试](https://docs.unity3d.com/Manual/managed-code-debugging.html) |

**本仓库边界。** `unitycli` 在检测到 `com.unity.pipeline` 时会[接管并停用其独立 server](../unitypkg/Editor/Infrastructure/UnityCliPipelineHandoff.cs)，且[不投影 Pipeline 包自身的 `[CliCommand]`](../unitypkg/Editor/ProjectTools/OfficialAttributeToolRegistry.cs)。不能仅凭官方包文档断言目标项目可直接执行 `unity command reload_file`，也不能把它当作已暴露的 `unitycli` Tool；需要先确认目标项目的包版本与实际能力目录。

**重载恢复的边界。** Unity 的代码重载会卸载/销毁并重新加载脚本程序集。[`InitializeOnLoad`](https://docs.unity3d.com/ScriptReference/InitializeOnLoadAttribute.html) 可在重编译后重新注册 Editor 回调；[`AssemblyReloadEvents`](https://docs.unity3d.com/ScriptReference/AssemblyReloadEvents.html) 有重载前后通知；[`SessionState`](https://docs.unity3d.com/ScriptReference/SessionState.html) 可保存会话内的键值基线，退出 Editor 后清空。由这些机制推得：重载后可恢复**监视意图**，不能保留旧委托/反射对象身份，也不能追溯重载窗口里未采到的赋值。[代码生命周期](https://docs.unity3d.com/Manual/programming-code-lifecycle.html)。Play 模式进入时是否重载还受版本及项目配置影响，不能把一次设置推作普遍保证。[进入 Play 时的重载配置](https://docs.unity3d.com/Manual/code-reloading-editor.html)。

**未经验证的 debugger 假说。** 特定 IDE/调试器也许有条件 tracepoint、logpoint 或数据断点，可在现有方法执行时打印字段，甚至不显式停住；所查的 Unity 官方托管调试文档仅保证断点、单步、变量检查，没有证明 Unity Editor 支持这些能力、字段写入断点的覆盖范围、日志回调接口或跨重载自动重绑。不能将这一假说作为官方 CLI 方案。[Unity 托管代码调试](https://docs.unity3d.com/Manual/managed-code-debugging.html)。
